# Master 서명 수신 후 자동 배포

2026-10-02 Master 지시에 따라 도우미 v1.1.1의 **승인 · 서명 · 전달** 이후 대화창의 완료 메시지 없이 이어서 처리한다. 기존 도우미 재설치·추가 토큰·개인키 전송은 필요 없다.

1. 준비된 요청과 동일한 서명 JSON이 `publisher/inbox/`에 전달되면 GitHub Actions가 자동 시작한다.
2. 고정 운영 공개키, 정확한 요청/payload, 순번 역행, 명시적으로 활성화한 배포 계획, 선행 버전, 공개 검토 기록과 불변 패키지 전체를 확인한다.
3. 실제 이전/새 Windows 실행파일 각각에서 운영 서명·변조 거부·무인증 다운로드·적용·복구·합성 설정/결과 보존을 확인한다.
4. 모두 통과하면 장기 배포 목록을 게시하고 공개 조회를 확인한 뒤 기존 Release를 정식으로 전환한다. 완료 기록과 요청 idle 전환은 함께 저장한다.

상태: [최근 완료 기록](../status.json) · [자동 배포 실행/오류](https://github.com/YoubinNa/TRADE-OPERATIONS-SUITE-UPDATES/actions/workflows/auto-publish-signed.yml). 도우미의 ‘자동 전달 완료’는 접수 완료이며 검증·게시 완료는 별도다. 일반 프로그램에서 최신 여부를 확인하면 게시된 버전을 받을 수 있다.

검증 실패 시 새 목록을 게시하지 않는다. 게시 후 공개 조회/Release 전환 중 실패하면 이미 검증된 목록은 유지하고 실행 실패로 표시한다. 같은 실행을 재실행하면 동일 서명을 재사용해 완료 단계를 복구하며 재서명은 필요 없다. 서로 다른 요청/동일 순번 충돌/동시 브랜치 변경은 거부한다. 처리 완료된 요청의 반복 실행은 아무것도 게시하지 않는다.

`publisher/plans/seq-N.json`은 후보 사전검증과 선행 전환을 위한 배포 게이트다. 다음 버전 준비 시 정확한 payload hash·선행 버전·공개 검토·Windows 후보 검증을 기록한다. 계획 등록만으로 Master 서명을 대신하지 않는다. 2026-10-03 사용자 명시 승인으로 seq-13 / v0.1.30을 준비했다. 이번 계획만 `legacy-import-once`이며 실제 v27 온라인 거부와 직접 ZIP 가져오기·복구, 새 v30의 서명된 온라인 적용·복구를 검사한다. v27 PC에서는 게시 후 ZIP 가져오기가 한 번 필요하다. User 배포와 새로운 launcher API는 별도 검토 대상이다.

이 자동화는 승인된 업데이트의 온라인 게시까지 담당한다. 사용자 PC의 다운로드·적용·재시작과 실제 업무 확인을 대신하지 않는다. 사용자 자료, 개인키, 개인 메일 자산이나 비공개 저장소 소스를 읽지 않는다. 공개 패키지와 합성 자료만 검사한다. 파일 내용의 공개 적정성 검토는 후보 준비 시 선행하며 자동 해시 검사로 대체하지 않는다.
